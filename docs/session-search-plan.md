## 1. 需求定义与范围裁定

原始提案 A1 是**跨项目全局会话搜索**，后裁定缩小为**项目内搜索**（用户自己的判断，评审认同）：

| 论据 | 内容 |
|---|---|
| 心智模型 | 找会话几乎必有「我知道在哪个项目」的前提；「连项目都忘了」是低频场景 |
| 低频场景的兜底 | 工具栏项目名/路径过滤先筛一遍，19 个项目的规模下绕路成本 ≈ 0 |
| 工程性 | 项目内是全局的**严格子集**：后端差别只在文件枚举集（单项目 `<mangled>/*.jsonl` vs 全部项目），扫描核/跳转链完全复用，先做窄的不锁死后路 |

**搜索的必须是内容而不是标题**：自动标题太 vague（「修复登录 bug」式标题哪都有），
对已加载列表做纯前端标题过滤解决不了真问题；真价值在**全文搜索该项目所有会话 jsonl**。
（标题过滤保留为「输入即时反馈」的第一档，见 §2。）

## 2. 交互设计（v2 终版）

### 2.1 两轮迭代记录

| 版本 | 方案 | 结论 |
|---|---|---|
| v1 | 搜索框**常驻**在展开项目的会话块首行 | ❌ 否决。输入控件是会话块里最重的元素（边框+底色+焦点环），低频动作不配常驻 UI；与 `3ecb1a3`「会话行操作收进右键菜单」是同一本账 |
| v2 | 入口收进**项目右键菜单「搜索会话」**（行尾 ⋯ 同源），点击后搜索框**按需出现**在会话块首行 | ✅ 终版。不搜索时零常驻元素，界面与现状完全一致 |

### 2.2 明确否决的备选（含理由，防止日后重新论证）

| 备选 | 否决理由 |
|---|---|
| 行内第三颗常驻图标按钮 | 行尾已有 ⋯ 和 +，再加一颗进一步压缩标题区；省一次点击的收益 < 每分钟都在付的视觉成本 |
| 浮层 popover（锚定项目行弹出） | 结果行复用不了 SessionRow 的交互（右键菜单/置顶/active 高亮带不过去）；需自带定位/出界钳制/点外关闭/内部滚动；跳转即关闭，无法**点开一个命中回来再点下一个**比对候选（原地过滤天然支持） |
| 复用顶部工具栏搜索框 | 那里是项目名/路径过滤，两个作用域的搜索混一个框会打架 |
| 模态弹窗 | 快速 scan-and-jump 动作用全窗口遮罩过重（对比：回收站/统计才是弹窗级功能） |

### 2.3 终版交互流程

1. **入口**：右键项目行（或点行尾 ⋯，同源）→「搜索会话」，插在「复制路径」之后、危险项分隔线之前。
   未展开的项目直接invoke：自动展开（结果要展示在会话块里，展开是自然副作用）。
2. **搜索框**：按需出现在会话块首行，出现即聚焦；复用 `.search-box/.search-input/.search-clear`
   的紧凑版形态。
3. **两段式搜索**：
   - 第一档（即时，纯前端）：按标题/摘要过滤已加载列表，零延迟，列表不空白；
   - 第二档（异步，后端）：300ms 防抖后全文搜索该项目所有 jsonl，结果**原地合并**；
     仅标题命中的行带「标题」小徽标；300ms 防抖窗口内重复输入作废迟到回包（世代号，
     与查看器分页 `d8b4958` 同一思路）。
4. **命中行**：复用 `SessionRow`——标题（关键词高亮 `<mark>`，取 `--accent-soft/--accent` 主题变量）
   + 片段行（首命中前后约 60 字符、高亮、两行截断）+ 右缘命中数徽标；顺序保持 mtime 倒序不变
   （与正常列表同一心智模型，不按命中数重排）。
5. **已置顶会话参与搜索**：正常列表里置顶会话被滤到顶部聚合区，但搜索必须召回（否则内容层面
   永远找不到）；命中行图钉呈已置顶态（accent 色）提示它同时在置顶区。
6. **点击命中 → 跳转**：打开右侧查看器并定位首个命中（自动加载所在分页、展开对应活动组），
   完全复用现有 `jumpTo` 跨分页链路，零新增跳转机制。
7. **状态行**：搜索中 spinner +「正在搜索会话内容…（标题过滤已生效）」；完成
   「N 个会话 · M 处命中」；无命中块内一行空态；失败就地贴状态行，不弹窗、不丢已过滤列表。
8. **收起闭环**：Esc 第一次清关键词 → 第二次收起搜索框；收起/切换项目一并重置（关键词不跨项目保留）。

### 2.4 上限口径

- 单文件命中沿用 `MAX_SEARCH_HITS = 200`（`lib.rs:249`）；
- 跨会话最多展示 50 个会话、每会话 1 条片段，超出折叠为「还有 N 个会话」一行。

## 3. PM 评审结论（2026-09-18）

**合格偏上，离出色差两条**（完整评审在对话中，此处记结论与待办）：

| 级别 | 问题 | 复活时必做 |
|---|---|---|
| **P0** | 无键盘路径：搜索要付「鼠标往返税」，名字带 fast 的工具里是硬伤 | 展开态 Ctrl+F（或侧栏聚焦时直接打字）唤出搜索 + 结果 ↑↓/Enter 导航；菜单项右侧加快捷键提示 |
| **P1** | 性能假设无退化兜底：大会话项目全文扫描可能数秒，spinner 变谎言 | 状态行进度态「已扫 N/M 个会话…」；关键词微调不全量重扫（前缀命中文件复用上轮结果） |
| P2 | 「标题」徽标与耗时数字是工程师审美 | 可做减法：先减这两个 |
| P2 | 可发现性刻意牺牲（右键入口不可见） | 实施时把 trade-off 写进 CLAUDE.md |
| P2 | 异步时序坑 | 搜索框必须在「会话加载中…」态就渲染并聚焦，不能等会话列表回来（原型瞬时渲染掩盖了此时序） |

## 4. 实现落点（复活时从这开始）

### 后端（`src-tauri/src/lib.rs`）

| 锚点 | 内容 | 复用方式 |
|---|---|---|
| `list_sessions`（`lib.rs:1217`） | mangle 定位项目目录 + 枚举 `.jsonl` + 首尾 64KB 元数据提取 | 新命令 `search_project_sessions(project_path, keyword)` 复用其定位/枚举 |
| `search_session_messages_impl`（`lib.rs:1702`） | 单文件全文搜索核（text 块 + tool_use 输入，跳过 thinking/tool_result，大小写不敏感） | **逐文件调用，按会话分组聚合返回**——本功能后端主体 ≈ 100 行胶水 |
| `SessionSearchHit`（`lib.rs:234`）/ `MAX_SEARCH_HITS`（`lib.rs:249`） | 命中结构与单文件上限 | 直接沿用 |
| 既有模式 | `spawn_blocking` 阻塞线程池跑扫描（与 `list_projects`/`get_usage_stats` 一致） | 照搬 |

### 前端

| 文件 | 改动 |
|---|---|
| `ContextMenu.tsx` | 项目组加「搜索会话」项（纯文字，无新图标） |
| `ProjectList.tsx` / `SessionRow.tsx` | 会话块按需渲染搜索框与状态行；SessionRow 加可选片段行/命中数/标题徽标 props |
| `App.tsx` | 每项目 `searchVisible` 状态 + 关键词；展开/收起重置；点击命中走既有 `loadSessionMessages` + `jumpTo` |
| `styles.css` | `.session-search*` / `.session-snippet` / `.hit-count` / `.title-only` / mark 主题适配；**无新按钮类**（清除复用 `.search-clear`） |

### 铁律核对清单

- 图标零新增（全用 `Icons.tsx` 既有组件）；
- 无新按钮类 → 无墨迹居中新债（清除按钮复用 `.search-clear` 的 flex 居中形态）；
- `<mark>` 颜色走主题变量，深浅两套自动适配；
- 会话文件路径校验沿用 canonicalize 体系（命令入参只有 project_path + keyword，
  返回的 file 路径用于既有打开链路，不新增路径信任面）。
